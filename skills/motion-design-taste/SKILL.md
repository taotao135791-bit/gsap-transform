# Motion Design Taste

The aesthetic and motion-language layer that sits **above** the GSAP API skills. Every GSAP page generated by an agent should pass through this skill first, then descend into the correct API skill.

## When to Use This Skill

Apply at the **start** of any task that produces an animated frontend interface — before writing GSAP code. Use when the user describes a brief, a vibe, references, or simply asks for "an animated landing page" without specifying. Output a one-line **Design Read** before any code, choose dial values, then route to the API skills.

**Related skills (this layer):** [motion-recipes](../motion-recipes/SKILL.md) for ready-made aesthetic × motion combinations, [motion-anti-slop](../motion-anti-slop/SKILL.md) for the deterministic checks, [motion-craft](../motion-craft/SKILL.md) for the command-style workflow (init, shape, animate, polish, audit).

**Related skills (API layer):** [gsap-core](../gsap-core/SKILL.md) for tweens and easing, [gsap-timeline](../gsap-timeline/SKILL.md) for sequencing, [gsap-scrolltrigger](../gsap-scrolltrigger/SKILL.md) for scroll-driven motion, [gsap-plugins](../gsap-plugins/SKILL.md) for SplitText/Flip/Draggable/MorphSVG, [gsap-react](../gsap-react/SKILL.md) and [gsap-frameworks](../gsap-frameworks/SKILL.md) for framework integration, [gsap-performance](../gsap-performance/SKILL.md) for 60fps work.

## Section 1 — Read the Brief Before Anything Else

Most AI-generated motion is bad because the model jumps straight to a default aesthetic and a default ease. Read the brief first.

### 1.A Signals to Read

1. **Page kind** — landing (SaaS / consumer / agency / event), portfolio (designer / developer / studio), redesign (preserve vs. overhaul), editorial / blog, product / app surface.
2. **Vibe words** the user used — "minimalist", "calm", "Linear-style", "Awwwards", "brutalist", "premium", "Apple-y", "playful", "editorial", "kinetic", "cinematic", "glassy", "dark tech".
3. **References** — URLs, screenshots, brands the user named or is competing with.
4. **Audience** — B2B procurement panel vs. design-conscious consumer vs. recruiter scanning a portfolio. The audience picks the aesthetic, not the agent's taste.
5. **Brand assets that already exist** — logo, palette, type, photography. For redesigns these are starting material, not optional input.
6. **Quiet constraints** — accessibility-first audiences, public-sector, regulated industries, kids' products. These constraints **override** aesthetic preference.

### 1.B Output a one-line Design Read before any code

Format: **"Reading this as: \<page kind\> for \<audience\>, with a \<vibe\> language, leaning toward \<aesthetic family\> and \<motion language\>."**

Examples:
- "Reading this as: B2B SaaS landing for technical buyers, with a Linear-style restrained language, leaning toward Geist + Tailwind utilities and a **restrained motion** mode (autoAlpha fades, short stagger, no scrub)."
- "Reading this as: solo designer portfolio for hiring managers, with an editorial / kinetic-type language, leaning toward a **cinematic motion** mode (SplitText reveals, pinned scroll-driven sections, magnetic cursor)."
- "Reading this as: redesign of a public-sector service site, with a trust-first language, leaning toward USWDS or GOV.UK Frontend and a **near-static motion** mode (≤200 ms autoAlpha, no parallax, full reduced-motion respect)."

### 1.C If the brief is genuinely ambiguous, ask exactly ONE question

Never dump multiple clarifying questions. Example: "Should this feel closer to Linear-clean or Awwwards-experimental?" If inference is confident, do not ask — declare the Design Read and proceed.

### 1.D Anti-Default Discipline

Avoid these LLM defaults unless the brief specifically asks for them:

- AI-purple gradients on dark mesh
- Centered hero with a single H1 over a glowing radial blur
- Three equal feature cards in a row
- Glassmorphism on every surface
- Inter + slate-900 + indigo accent
- Bouncing/elastic ease on every entrance
- Parallax on every section, scrub on every block
- Animated gradient backgrounds running forever in the corner

These are the slop pool. Reach past them deliberately, not by accident.

## Section 2 — The Three Dials

After the Design Read, set three dials that gate every layout, motion, and density decision below.

| Dial | 1 — low | 10 — high |
|------|---------|-----------|
| **MOTION_INTENSITY** | Static, near-zero motion | Cinematic, pinned scrub, kinetic typography |
| **DESIGN_VARIANCE** | Perfect symmetry, centered, predictable | Asymmetric, overlap, grid-breaking |
| **VISUAL_DENSITY** | Art-gallery airy | Cockpit, packed data |

**Baseline:** `MOTION_INTENSITY: 6 / DESIGN_VARIANCE: 7 / VISUAL_DENSITY: 4`. Override conversationally based on Design Read; never ask the user to "edit a config file".

### 2.A Dial Inference Table

| Brief signal | MOTION_INTENSITY | DESIGN_VARIANCE | VISUAL_DENSITY |
|---|---|---|---|
| "minimalist / clean / calm / Linear-style / editorial" | 3-4 | 5-6 | 2-3 |
| "premium consumer / Apple-y / luxury / brand" | 5-7 | 7-8 | 3-4 |
| "playful / Dribbble / Awwwards / experimental / agency" | 8-10 | 9-10 | 3-4 |
| "landing / portfolio / marketing (default)" | 6-8 | 7-9 | 3-5 |
| "trust-first / public-sector / regulated / accessibility-critical" | 1-3 | 3-4 | 4-5 |
| "redesign — preserve" | match existing +1 | match existing | match existing |
| "redesign — overhaul" | +2 | +2 | match existing |

### 2.B Use-Case Presets

| Use case | MOTION | VARIANCE | DENSITY |
|---|---|---|---|
| Landing (mainstream SaaS) | 6 | 7 | 4 |
| Landing (creative agency) | 9 | 9 | 3 |
| Landing (premium consumer) | 6 | 7 | 3 |
| Portfolio (designer / studio) | 8 | 8 | 3 |
| Portfolio (developer) | 5 | 6 | 4 |
| Editorial / blog | 4 | 6 | 3 |
| Public-sector service | 2 | 3 | 5 |

### 2.C How the dials drive output

These exact variable names are referenced throughout this document and the sibling skills. Do not rename them (`LAYOUT_VARIANCE`, `ANIM_LEVEL` are not valid aliases). [motion-recipes](../motion-recipes/SKILL.md) and [motion-anti-slop](../motion-anti-slop/SKILL.md) read the same dials.

## Section 3 — Typography Hard Rules

Typography is half the design. Wrong type, no amount of GSAP saves it.

- **Discouraged as default:** `Inter`, `Roboto`, `Arial`, system stacks. Default-reaching for Inter is the single most-tested AI tell.
- **Reach for instead** (rotate; do not reuse the same font across consecutive projects): `Geist`, `Geist Mono`, `Satoshi`, `Cabinet Grotesk`, `PP Neue Montreal`, `GT Walsheim`, `Söhne`, `ABC Diatype`, `Inter Display` (different from `Inter`), `Migra Sans`.
- **Override:** `Inter` is acceptable when the brief explicitly asks for a Linear-style / neutral / public-sector feel.

### 3.A Serif Discipline

Serif as default for "creative / premium / editorial" briefs is the second most-tested AI tell. Serif is acceptable **only** when one of these is true:

- The brand brief literally names a serif font, OR
- The aesthetic family is genuinely editorial / luxury / publication / manuscript / heritage / vintage AND the agent can articulate why this specific serif fits this specific brand.

When a serif is justified, rotate from: PP Editorial New, GT Sectra Display, Reckless Neue, Tiempos Headline, Recoleta, Cormorant Garamond, EB Garamond, IvyPresto, Migra, Saol Display, Domaine Display, Canela.

**Specifically banned as defaults:** `Fraunces`, `Instrument_Serif` (the two LLM-favorite display serifs).

### 3.B Mixed-Family Emphasis Ban

For emphasis inside a headline ("and `spatial` design"), use **italic or bold of the same font**. Do not inject a random serif word into a sans headline (or vice versa). Mixed-family emphasis reads as amateur.

### 3.C Italic Descender Clearance

When italic is used in display type with descender letters (`y g j p q`), `leading-none` clips. Use `leading-[1.1]` minimum and reserve `pb-1` on the wrapping element. SplitText animations on display italics must respect this.

## Section 4 — Color Hard Rules

- **One accent color per project.** Saturation under 80% by default. The same accent appears in nav CTA, hero CTA, and footer CTA — do not switch from rose in section 1 to teal in section 7.
- **The Lila Rule:** AI-purple / blue-glow gradients are discouraged as default. Use neutral bases (Zinc / Slate / Stone) with a singular high-contrast accent (Emerald, Electric Blue, Deep Rose, Burnt Orange).
- **Override:** purple is fine when the brand explicitly asks for it; execute with intent (consistent palette, harmonized neutrals, restrained gradients).
- **No pure black on light, no pure white on dark.** Always tint shadows and surfaces toward the page's hue.

### 4.A Premium-Consumer Palette Ban

For premium-consumer briefs (cookware, wellness, artisan, luxury, heritage craft, DTC home), the LLM default is **warm beige/cream + brass/clay/oxblood + espresso text**. This palette is banned as the default reach. Rotate to one of these alternatives instead:

- **Cold Luxury** — silver-grey + chrome + smoke
- **Forest** — deep green + bone + amber
- **Black & Tan** — true off-black + warm tan, sharp contrast
- **Cobalt + Cream** — saturated blue against a single neutral
- **Terracotta + Slate** — warm rust against cool grey
- **Olive + Brick + Paper** — muted olive plus brick-red

The beige+brass+espresso palette is acceptable **only** when the brand brief explicitly names those colors, or the brand identity is genuinely vintage / artisan / warm-craft.

## Section 5 — Layout Hard Rules

- **Hero MUST fit in the initial viewport.** Headline ≤ 2 lines on desktop, subtext ≤ 20 words and ≤ 4 lines, CTAs visible without scroll. Use `min-h-[100dvh]` (never `h-screen`) to avoid mobile address-bar jumping.
- **Hero stack discipline.** Maximum 4 text elements: optional eyebrow OR brand strip (pick zero or one), headline, subtext, CTAs (1 primary + max 1 secondary). Trust-strip / pricing teaser / feature bullets do **not** belong in the hero.
- **Anti-Center Bias.** When `DESIGN_VARIANCE > 4`, replace the centered hero with split (50/50), left-aligned content + right asset, asymmetric whitespace, or scroll-pinned structure. Centered hero is acceptable only for editorial / manifesto / launch-announcement briefs.
- **Eyebrow Restraint.** Maximum 1 eyebrow per 3 sections. If section A has an eyebrow, the next 2 sections cannot. Default is no eyebrow.
- **CTA Wrap Ban.** Primary CTA labels must fit on one line at desktop and use ≤ 3 words ("Start free", "View work"). Two CTAs with the same intent ("Get in touch" + "Contact us" + "Let's talk") on one page is shipping broken work — pick one label.
- **Shape Consistency Lock.** Pick one corner-radius scale and stick to it: all-sharp (0), all-soft (12-16 px), all-pill (full radius for interactive). Mixed scales need a documented rule.
- **Grid over flex-math.** `grid grid-cols-1 md:grid-cols-3 gap-6` over `w-[calc(33%-1rem)]`.
- **Zigzag Alternation Cap.** Maximum 2 consecutive image-text-split sections. The 3rd consecutive zigzag is broken work — break with a full-width section, vertical-stack section, marquee, or different layout family.

## Section 6 — Motion Language (Three Modes)

Pick one motion mode per project based on `MOTION_INTENSITY`. Every duration, ease, and stagger inherits from the mode unless a recipe overrides it.

### 6.A Restrained — `MOTION_INTENSITY: 1-4`

Functional, near-invisible, prioritizes content. Suits: B2B SaaS (Linear-style), public-sector, regulated, accessibility-critical, editorial reading.

```javascript
gsap.defaults({ duration: 0.4, ease: "power2.out" });
// Entrance: autoAlpha + small y, stagger 0.04
gsap.from(".item", { autoAlpha: 0, y: 8, stagger: 0.04, duration: 0.35 });
```

- **duration:** 0.2 – 0.5 s
- **ease:** `power1.out`, `power2.out`, `none` for scrub
- **stagger:** 0.03 – 0.06 s
- **scroll:** prefer `toggleActions: "play none none reset"` over scrub; no pinning unless absolutely necessary
- **transforms:** `autoAlpha`, `y`, `xPercent` only — no `scale`, no `rotation`

### 6.B Expressive — `MOTION_INTENSITY: 5-7`

Confident, brand-forward, choreographed. Default for most landing pages and portfolios.

```javascript
gsap.defaults({ duration: 0.6, ease: "power3.out" });
const tl = gsap.timeline({ defaults: { ease: "power3.out" } });
tl.from(".eyebrow", { autoAlpha: 0, y: 12, duration: 0.4 })
  .from(".headline-line", { yPercent: 100, stagger: 0.08, duration: 0.6 }, "<0.1")
  .from(".cta", { autoAlpha: 0, y: 8, duration: 0.4 }, "<0.2");
```

- **duration:** 0.4 – 0.9 s
- **ease:** `power2.inOut`, `power3.out`, `expo.out`, `circ.out`. Avoid `back.out` and `elastic.*` as defaults.
- **stagger:** 0.05 – 0.12 s; use `from: "edges"` or `from: "center"` when it serves the composition
- **scroll:** mix `scrub: 1` for hero parallax with `toggleActions` for section reveals; pin the hero only if it earns it
- **transforms:** `y`, `xPercent`, `autoAlpha`, `clipPath`, modest `scale: 0.95 → 1`

### 6.C Cinematic — `MOTION_INTENSITY: 8-10`

High-craft, choreographed, scroll-driven, kinetic typography, magnetic cursors. Suits: agency / studio sites, awwwards-targeted, motion-led portfolios.

```javascript
import { SplitText } from "gsap/SplitText";
gsap.registerPlugin(SplitText, ScrollTrigger);

const split = SplitText.create(".display", { type: "lines, words", mask: "lines" });
gsap.from(split.words, {
  yPercent: 110,
  rotation: 6,
  stagger: 0.04,
  duration: 0.9,
  ease: "expo.out"
});

gsap.timeline({
  scrollTrigger: { trigger: ".scene", start: "top top", end: "+=2000", pin: true, scrub: 1 }
})
  .to(".bg", { yPercent: -30, ease: "none" })
  .to(".fg", { yPercent: -8, ease: "none" }, "<");
```

- **duration:** 0.6 – 1.4 s; long durations only on hero and pinned sections
- **ease:** `expo.out`, `power4.out`, `power3.inOut`, `none` (scrub). `CustomEase` allowed when the brand has a defined motion curve.
- **stagger:** 0.03 – 0.1 s, often `from: "random"` for kinetic type
- **scroll:** pinned scenes with `scrub: 1`, parallax layers, ScrollTrigger.batch for grid reveals
- **transforms:** kinetic SplitText, MorphSVG, Flip transitions, magnetic cursor (Inertia + quickTo)

### 6.D Mode-Crossing Bans

- **Bounce / elastic on entrance** is banned in Restrained, discouraged in Expressive, allowed in Cinematic only for branded character moments — not on every card hover.
- **Parallax on every section** is banned in all modes. Parallax earns one or two sections; the rest hold still.
- **Animated background gradients running forever** are banned in all modes. They drain attention from content.

## Section 7 — Accessibility (prefers-reduced-motion)

Every project must respect prefers-reduced-motion. Without this, the page literally hurts users with vestibular disorders.

```javascript
const mm = gsap.matchMedia();

mm.add(
  { isMotionOK: "(prefers-reduced-motion: no-preference)", isReduced: "(prefers-reduced-motion: reduce)" },
  (ctx) => {
    const { isMotionOK } = ctx.conditions;
    if (isMotionOK) {
      // full motion language (Section 6)
      gsap.from(".item", { autoAlpha: 0, y: 12, stagger: 0.06, duration: 0.5 });
    } else {
      // reduced: no movement, instant reveal, kill scroll-driven motion
      gsap.set(".item", { autoAlpha: 1, y: 0 });
    }
  }
);
```

- ScrollTrigger scrub and pin should be disabled or replaced with `toggleActions: "play none none none"` under reduced-motion.
- Marquees, infinite loops, and parallax should stop entirely.
- See [gsap-core](../gsap-core/SKILL.md) `gsap.matchMedia()` section for the full API.

## Section 8 — Pre-Flight Check (run before shipping)

Run mechanically before declaring done. A single failure means the work is not shippable.

1. **Design Read** declared in one line at the top of the response.
2. Three dials are stated explicitly (`MOTION_INTENSITY`, `DESIGN_VARIANCE`, `VISUAL_DENSITY`).
3. **Typography:** no `Inter` / `Roboto` / `Arial` as default unless brief justifies; no mixed-family emphasis inside a single headline.
4. **Color:** one accent color used consistently from nav to footer; no AI-purple gradient unless brief asks; no pure black on light. Verify with `getComputedStyle` that every supposed accent element actually renders the declared accent token — a low-specificity accent rule silently overridden by a sibling rule is a [motion-anti-slop](../motion-anti-slop/SKILL.md) **F6** failure.
5. **Hero:** fits in `100dvh`, headline ≤ 2 lines, subtext ≤ 20 words, ≤ 4 text elements total.
6. **Layout:** ≤ 1 eyebrow per 3 sections, ≤ 2 consecutive zigzag splits, no two CTAs with same intent on the page.
7. **Motion mode** matches `MOTION_INTENSITY` band (Section 6); duration / ease / stagger fall inside the band.
8. **No `back.out` / `elastic.*` as defaults.** No scrub on every section. No infinite background animation.
9. **prefers-reduced-motion** branch exists via `gsap.matchMedia()` (Section 7).
10. **Cleanup** — every component using GSAP either uses `useGSAP` ([gsap-react](../gsap-react/SKILL.md)) or `gsap.context()` + `ctx.revert()` on unmount ([gsap-frameworks](../gsap-frameworks/SKILL.md)).
11. **ScrollTrigger** is on the timeline / top-level tween, not inside a child tween (see [gsap-scrolltrigger](../gsap-scrolltrigger/SKILL.md)).
12. **Performance** — animated properties are transforms or `autoAlpha`, not `width / height / top / left` ([gsap-performance](../gsap-performance/SKILL.md)).

For the deterministic-rule version of this list, run [motion-anti-slop](../motion-anti-slop/SKILL.md).

## Section 9 — Bridge to GSAP API Skills

After the Design Read and dials, route to the right API skill:

| Brief contains… | Load skill | Why |
|---|---|---|
| "single tween / fade in / hover effect / basic animation" | [gsap-core](../gsap-core/SKILL.md) | Core API, easing, stagger |
| "sequence / multi-step / choreograph / keyframes" | [gsap-timeline](../gsap-timeline/SKILL.md) | timeline + position parameter |
| "scroll-driven / parallax / pin / scrub / on-scroll reveal" | [gsap-scrolltrigger](../gsap-scrolltrigger/SKILL.md) | ScrollTrigger config + cleanup |
| "kinetic typography / SplitText reveal / morph icon / draggable / magnetic cursor / flip layout" | [gsap-plugins](../gsap-plugins/SKILL.md) | SplitText, MorphSVG, Flip, Draggable, Inertia |
| "map scroll to value / clamp / random / snap / scoped selector" | [gsap-utils](../gsap-utils/SKILL.md) | gsap.utils helpers |
| "React / Next.js / useGSAP / cleanup on unmount" | [gsap-react](../gsap-react/SKILL.md) | useGSAP hook + scope |
| "Vue / Nuxt / Svelte / SvelteKit / onMounted" | [gsap-frameworks](../gsap-frameworks/SKILL.md) | gsap.context + lifecycle |
| "smooth 60fps / jank / mouse follower / many elements" | [gsap-performance](../gsap-performance/SKILL.md) | quickTo, transforms, batching |

Load **multiple** API skills when the brief crosses concerns (e.g. a React portfolio with pinned scroll → load [gsap-react](../gsap-react/SKILL.md) + [gsap-scrolltrigger](../gsap-scrolltrigger/SKILL.md) + [gsap-plugins](../gsap-plugins/SKILL.md)).

## Best Practices

- ✅ Declare the **Design Read** in one line before any code.
- ✅ Set the **three dials** explicitly; reference them by their canonical names.
- ✅ Pick **one motion mode** per project from Section 6 and let duration / ease / stagger inherit from it.
- ✅ Bridge to API skills via Section 9 instead of restating GSAP API rules.
- ✅ Run the **Pre-Flight Check** (Section 8) mechanically; a single failure blocks shipping.
- ✅ Always wire **prefers-reduced-motion** via `gsap.matchMedia()` (Section 7).

## Do Not

- ❌ Skip the Design Read and jump straight to GSAP code with default `Inter` + `power2.out` + 0.5 s.
- ❌ Default-reach for AI-purple gradients, glassmorphism on every surface, centered hero, three equal cards.
- ❌ Default-reach for `Fraunces` / `Instrument_Serif` whenever the brief sounds creative; serif is restricted (Section 3.A).
- ❌ Mix font families for emphasis inside a single headline; use italic or bold of the same family.
- ❌ Use `back.out` / `elastic.*` as default eases; reserve them for branded character moments only.
- ❌ Add parallax / scrub / pin to every section — earn each one.
- ❌ Ship without a `prefers-reduced-motion` branch; that is broken work.
- ❌ Restate GSAP API rules in this skill; route to the API skills (Section 9) instead.
